# E0.1 · Monorepo (pnpm + Turborepo)

**Decisão pendente do Gabriel:** nenhuma. **Sensível para segurança:** não (sem revisor de segurança). **Dependências:** nenhuma.

## 1. Objetivo e critério de aceite

Backlog: "Monorepo (pnpm + Turborepo): `apps/mobile`, `apps/api`, `packages/match-engine`, `packages/volley-rules`". **Aceite:** "`pnpm build` e `dotnet build` passam do zero".

"Do zero" = clone novo, sem caches do repositório, em Windows e sem depender de nada do Windows (a CI da E0.4 roda em Ubuntu).

**Fora do escopo:** módulos e `Sacou.Shared` (E0.2); ESLint, Prettier, `.editorconfig`, analisadores (E0.3); workflows (E0.4); Expo Router, Unistyles, temas e identificadores de app (E4.1/M3); formações em `volley-rules` (E1.1).

## 2. Decisões técnicas

Versões conferidas em 30/10/2026 no registro npm, NuGet, metadados do .NET e template oficial `expo-template-blank-typescript@sdk-58`.

| Item | Versão | Observação |
|---|---|---|
| Node | `engines: >=22.13.0 <23`; `.nvmrc` 22.20.0 | Mínimo do Expo 58 na linha 22 |
| pnpm | `packageManager: pnpm@12.16.1`; `engines.pnpm: 12.16.1` | |
| Turborepo | `turbo` 2.11.10 | Política oficial: pnpm 8+. Não há nota explícita sobre o pnpm 12; validar pelo T3 |
| TypeScript | 6.0.3 | **Não usar a 7.0.2 (`latest`):** o template do SDK 58 fixa `~6.0.3` e ferramentas que usam a API do compilador, como typescript-eslint (E0.3), ainda dependem da 6 |
| Vitest / Vite | 5.0.5 / 8.3.5 | Vite é peer obrigatório; declarar |
| Expo | `expo ~58.0.21`, `react 19.3.0`, `react-native 0.88.1`, `@types/react ~19.3.0` | Exatamente o template do SDK 58 (RN e React são fixados pelo SDK) |
| .NET | `global.json`: SDK 10.0.403, `rollForward: latestPatch`, `allowPrerelease: false`, `test.runner: Microsoft.Testing.Platform` | |
| Testes .NET | `xunit.v3.mtp-v2` 4.0.2, `Microsoft.AspNetCore.Mvc.Testing` 10.0.14 | O `dotnet test` do SDK 10 só funciona com MTP desse jeito; sem `Microsoft.NET.Test.Sdk` e sem `xunit.runner.visualstudio` |

- **Versões JS compartilhadas** (`typescript`, `vitest`, `vite`) ficam em `catalog:` no `pnpm-workspace.yaml`, com versão exata. **NuGet** usa `Directory.Packages.props`.
- **`nodeLinker`:** manter o padrão `isolated`. O Expo suporta instalação isolada desde o SDK 54 e configura o Metro sozinho; `hoisted` é o plano B documentado, mas permite dependência não declarada. **Não** criar `metro.config.js` com `watchFolders`/`extraNodeModules` nem usar `shamefullyHoist`/`publicHoistPattern`. Se T4 falhar por resolução de módulo mesmo após investigar a causa, trocar para `nodeLinker: hoisted`, reinstalar e registrar o motivo no ADR.
- **Scripts de instalação:** no pnpm 11+ `strictDepBuilds` é `true` e a instalação falha com script não revisado. Resolver cada pacote em `allowBuilds`: `false` por padrão, `true` só se o build ou teste quebrar sem ele, com o motivo no ADR. Não desligar `strictDepBuilds` nem reduzir `minimumReleaseAge` (padrão 1 dia).
- **`pnpm build`** = `turbo run build`:
  - `packages/*`: `tsc -p tsconfig.build.json` gera `dist/` (ESM + `.d.ts`), consumido via `exports`.
  - `apps/mobile`: `tsc --noEmit && expo export --platform android --output-dir dist`. Não exige conta Expo e prova que o Metro resolve os pacotes do workspace, algo que só o typecheck não prova. Android basta aqui.
- **`apps/api` fica fora do grafo do Turborepo:** sem `package.json`, não entra no workspace do pnpm. `Sacou.slnx` na raiz faz `dotnet build` e `dotnet test` funcionarem na raiz. Motivo: `pnpm build` não exige .NET, o MSBuild tem cache incremental próprio e a CI pode separar os jobs. Atalhos na raiz: `build:api`, `test:api`.
- **Layout .NET:** `apps/api/src/Sacou.Api` e `apps/api/tests/Sacou.Api.Tests`, seguindo `docs/produto.md` (a E0.2 acrescenta o resto ali).

## 3. Sub-passos

Criar a branch `task/E0.1-monorepo`. Comitar também este plano.

1. **Raiz:** `package.json` (privado; `packageManager`, `engines`; scripts `build`, `typecheck`, `test`, `build:api`, `test:api`; `turbo` e `typescript` em dev), `pnpm-workspace.yaml` (`apps/mobile`, `packages/*`; catálogo; `allowBuilds`), `turbo.json`, `.nvmrc`, `pnpm-lock.yaml` (comitado).
   - `turbo.json`: `build` (`dependsOn: ["^build"]`, `outputs: ["dist/**"]`); `typecheck` e `test` (`dependsOn: ["^build"]`, sem outputs).
2. **Fim de linha:** `.gitattributes` com `* text=auto eol=lf` e binários marcados (`*.png`, `*.jpg`, `*.webp`, `*.ttf`). Fazer antes dos demais arquivos. **`.gitignore`:** acrescentar `*.tsbuildinfo`, `coverage/`, `TestResults/`, `.vs/`, `apps/mobile/android/`, `apps/mobile/ios/`, `expo-env.d.ts`.
3. **TypeScript:** `tsconfig.base.json` só com rigor, sem opções de módulo: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `forceConsistentCasingInFileNames`, `skipLibCheck`. `tsconfig.lib.json` estende a base: `module`/`moduleResolution: NodeNext`, `target: ES2022`, `lib: ["ES2022"]` (sem DOM, para garantir TS puro), `declaration`, `verbatimModuleSyntax`.
4. **`packages/volley-rules` e `packages/match-engine`** (`@sacou/volley-rules`, `@sacou/match-engine`; privados, `type: module`, `exports` com `types` e `default` em `dist/`), cada um com `package.json`, `tsconfig.json` (`noEmit`, inclui testes), `tsconfig.build.json` (exclui `*.test.ts`, `rootDir: src`, `outDir: dist`), `src/index.ts`, `src/smoke.test.ts`.
   - Scripts: `build`, `typecheck: tsc --noEmit`, `test: vitest run --dir src`.
   - Exportar só a constante `PACKAGE_NAME`. É provisória: E1.1 e E2.1 removem. Não mover `docs/dominio/formacoes.json`.
   - `match-engine` depende de `@sacou/volley-rules` (`workspace:*`) porque a E2.3 precisa dele; isso também prova a ordem topológica do build.
   - Imports explícitos de `vitest`, sem globais: o TS 6 usa `types: []` por padrão.
5. **`apps/mobile`** (`@sacou/mobile`, privado): `package.json` (`main: index.ts`; dependência dos dois pacotes via `workspace:*`), `app.json` (nome `Sacou`, slug `sacou`; sem `bundleIdentifier`/`package`, sem assets), `tsconfig.json` (`extends: ["expo/tsconfig.base", "../../tsconfig.base.json"]`, nessa ordem), `index.ts` (`registerRootComponent`), `App.tsx`, `src/strings/pt-BR.ts`. A tela mostra o texto "Sacou" e referencia `PACKAGE_NAME` dos dois pacotes, para que o bundle os inclua. Sem Babel/Metro config. Não usar imports profundos de `react-native/Libraries/*` (erro de tipo no SDK 58). Sem testes aqui: Turborepo ignora o pacote em `test`.
6. **.NET:** na raiz, `global.json`, `Sacou.slnx`, `Directory.Packages.props` e `Directory.Build.props` (`net10.0`, `Nullable`, `ImplicitUsings`, `TreatWarningsAsErrors`).

   - **Não declarar `public partial class Program`:** no .NET 10 é gerada automaticamente e a declaração manual gera o aviso ASP0027, que quebraria o build.
   - `Sacou.Api.Tests`: `OutputType` Exe, referência a `Sacou.Api`, `HealthEndpointTests` com `WebApplicationFactory<Program>`.
7. **Docs:**
   - `docs/arquitetura/adr/0001-monorepo-pnpm-turborepo.md`, curto: versões e por que TS 6; `isolated` e plano B; o que `build` faz no app; API fora do Turborepo; slnx na raiz; `allowBuilds` aprovados.

## 5. Riscos e perguntas em aberto

- **SDK 58 é recente (guia de atualização de 21/10/2026).** O build nativo só será exercitado no M3 (EAS), e `expo export` não prova build nativo: um problema de `isolated` pode aparecer só lá. A saída é o plano B, de custo baixo (uma linha + reinstalar). Módulos nativos de terceiros podem atrasar para o RN 0.88: Reanimated, Worklets e Expo Router já estão listados no SDK 58, mas **não encontrei confirmação do Unistyles** (3.7.0 declara `react-native >=0.81`). A E4.1 deve validar isso cedo; se falhar, as saídas são esperar a correção ou voltar ao SDK 57, e não mudar a decisão de arquitetura sem falar com o Gabriel.
- **pnpm 12 é uma reescrita em Rust**, com rejeição de chaves desconhecidas no `pnpm-workspace.yaml` (`ERR_PNPM_UNRECOGNIZED_WORKSPACE_SETTINGS`) quando a versão está fixada. Turborepo sem nota explícita de suporte à linha 12: se T3 falhar, reportar antes de trocar a versão.
- **Hermes no Ubuntu:** `expo export` compila bytecode, com binário específico da plataforma; só validado em Windows aqui. A E0.4 confirma. Se o tempo do build pesar na CI, separar o `export` num script próprio é simples.
- **Variáveis no Turborepo:** se o `expo export` falhar por variável removida pelo modo estrito, declarar só essa variável em `passThroughEnv`, nunca desligar o modo estrito.
- **`CLAUDE.md`:** o preenchimento de Comandos foi pedido pelo orquestrador. Se o sistema de permissões bloquear essa edição, o desenvolvedor deve reportar em vez de contornar.
- **E0.4 deve:** ler a versão do pnpm do `packageManager` (sem repetir), Node do `.nvmrc`, .NET do `global.json`, e confirmar que `pnpm/action-setup` aceita pnpm 12.
- **Divergência documental sem efeito aqui:** `docs/produto.md` põe os golden em `tests/golden/`; `docs/decisoes.md` (que prevalece) põe em `packages/volley-rules`. A E1.1 segue `decisoes.md`.
- **Superfície de ataque:** só `GET /health`, sem dados e sem deploy nesta tarefa. Sem dado pessoal novo.
- **Perguntas em aberto:** nenhuma.

## 6. Desvios na implementação

- **`CLAUDE.md`:** a nota de ambiente virou um bloco com o `export` completo (PATH do .NET, `NUGET_PACKAGES`, `TEMP`, `TMP`), maior que a "nota do PATH do .NET" do passo 7. Motivo: cada sessão começa do zero e o C: tem pouco espaço. Registrado no ADR 0001.
- **`allowBuilds`:** chave não declarada, porque nenhuma dependência tem script de instalação. Registrado no ADR 0001.
- **`turbo.json`:** `globalDependencies` acrescentado na revisão (ciclo 1), pois os tsconfigs da raiz não invalidavam o cache.
- **`apps/mobile/App.tsx`:** `PACKAGE_NAME` é referenciado por `testID`, só para manter os imports no bundle. Registrado no ADR 0001.
